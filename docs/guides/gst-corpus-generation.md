# GST Legal RAG Corpus Generation

This guide explains how the GST Legal RAG corpus files are generated from the vendored JSONL source data.

## Overview

The GST dataset consists of two source JSONL files that are vendored in the repository:

- **Source location**: `data/rag/gst_legal_rag/`
- **questions.jsonl**: 76 question-answer pairs with reference passage IDs
- **documents.jsonl**: 5,263 legal passages (ATO Legal Database)

The corpus preparation script converts `documents.jsonl` into individual `.txt` files for ChromaDB ingestion.

## Data Flow

```
data/rag/gst_legal_rag/
├── documents.jsonl          (5,263 passages)
├── questions.jsonl          (76 Q&A pairs)
└── corpus_files/           (generated by prepare_gst_legal_rag_corpus.py)
    ├── AID_*.txt            (5,263 individual text files)
    └── ...
```

## Corpus File Format

Each generated `.txt` file follows this structure:

```
ID: {passage_id}
Title: {title}

{text body}

Footnotes:
{footnotes}
```

**Conditional sections:**
- `ID:` line - Always included
- `Title:` line - Only when title is present (all GST docs have titles)
- Text body - Always included
- `Footnotes:` section - Only when footnotes present (all GST docs have `footnotes=null`)

## Generation Script

**Script**: `scripts/prepare_gst_legal_rag_corpus.py`

### How it works

1. **Reads JSONL**: Parses `documents.jsonl` line by line
2. **Extracts fields**: Gets `id`, `title`, `text`, `footnotes` from each JSON record
3. **Sanitizes filename**: Converts passage IDs to filesystem-safe names by replacing `/` and `\` with `_`
4. **Builds content**: Formats fields according to corpus structure above
5. **Writes file**: Saves as `{sanitized_id}.txt` in `corpus_files/` subdirectory

### Running the script

```bash
# Default (reads from data/rag/gst_legal_rag/, writes to corpus_files/)
uv run python scripts/prepare_gst_legal_rag_corpus.py

# Custom paths
uv run python scripts/prepare_gst_legal_rag_corpus.py \
  --cache-dir /path/to/documents.jsonl \
  --output-dir /path/to/corpus_files

# Force overwrite existing files
uv run python scripts/prepare_gst_legal_rag_corpus.py --force-refresh
```

### Expected output

```
Corpus exported to: data/rag/gst_legal_rag/corpus_files
Files created: 5263
```

## Source Data Schema

### documents.jsonl

Each line contains a JSON object with the following schema:

```json
{
  "id": "AID_AID2001271_00001_sec10_c1_s1",
  "title": "Decision",
  "text": "No, the entity is not making a GST-free supply...",
  "footnotes": null
}
```

### questions.jsonl

Each line contains a JSON object with the following schema:

```json
{
  "id": "1",
  "question": "Is the sale of honey subject to GST?",
  "answer": "According to Document 1, Honey is GST-free...",
  "relevant_passage_id": "GII_GSTIIFL1_NAT_ATO_00001_sec499_c1_s1"
}
```

## Filename Sanitization

Passage IDs from the source JSONL may contain characters unsafe for filesystems. The script sanitizes IDs by:

1. Replacing `/` with `_`
2. Replacing `\` with `_`

**Example**: `GII_GSTIIFL1/NAT/ATO/00001_sec499_c1_s1` → `GII_GSTIIFL1_NAT_ATO_00001_sec499_c1_s1.txt`

## ChromaDB Collection

The `corpus_files/` directory stem (`gst_legal_rag`) becomes the ChromaDB collection name, automatically isolating GST vectors from the Legal RAG Bench dataset.

## Verification

After corpus generation, verify:

```bash
# Count generated files
ls data/rag/gst_legal_rag/corpus_files/*.txt | wc -l
# Expected: 5263

# Check file format
head -5 data/rag/gst_legal_rag/corpus_files/AID_*.txt
```
